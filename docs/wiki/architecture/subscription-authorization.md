# 订阅授权与内部模型传输边界

## 背景与决策

订阅账户具有可续期授权和动态短期令牌，不能当作固定 API Key 复制到多个厂商配置。
授权中心负责账户事实，模型与厂商负责独立连接配置；两者分离才能在退出后统一使所有绑定失效。

## 当前规则

- 每个部署实例只有一个 GitHub Copilot 账户槽位。桌面和 Web 共用服务端实现，不在独立部署之间同步凭据。
- 账户记录保存加密 OAuth 凭据和单调递增的凭据代次。provider 只保存账户引用，不保存 OAuth/Copilot token。
- 登录是有截止时间的后端设备码会话。状态 GET 不触发远程请求；等待间隔和减速以 GitHub 响应为准。
- 失败、取消和过期不能覆盖有效账户；退出与重新授权通过代次校验阻止旧回调恢复授权。
- 平台凭据库使用独立本地主密钥与 AES-GCM。恢复已保存授权需要数据库和对应凭据目录；
  密钥丢失时不得自动生成并覆盖既有密文，应恢复原目录或由用户退出后重新授权。
- Web 使用 `AI_NOVEL_CREDENTIALS_DIR` 指定持久化私有目录；默认在服务端 `storage/credentials`。
  桌面使用 userData 下的 `credentials`。凭据目录不属于日志包或普通数据库导出内容。
- 桌面打开 GitHub 登录通过受限 IPC：只接受主渲染器 sender，仅打开固定 HTTPS 设备授权页面，
  不接收任意 URL，也不把应用访问令牌注入外部浏览器。Web 使用经过后端校验的 GitHub 验证链接。
- 订阅错误应保持类型化，不作为输出格式问题进入 JSON 修复，不因账户失效静默切换到其他厂商。
- Copilot 需重新授权使用 `COPILOT_AUTH_REQUIRED` 与 HTTP 409，不能使用应用访问鉴权的 401；
  否则前端会把上游订阅失效误当成应用访问令牌过期，跳转到错误入口。
- `platform/llm/subscription-proxy` 通过注入端口访问凭据，以标准 fetch 接入现有 SDK；
  所有绑定共享账户发送许可和 Retry-After 冷却，代理不自行重试或重放生成。
- 目录按上游显式端点选择 Chat 或 Responses，未知能力不能按模型名称猜测。
  目录、连接测试、正式调用、顶部选择与快速配置读取同一绑定/就绪事实。
- Copilot 的编辑器、插件、集成标识、User-Agent 与 API 版本属于上游兼容协议，不是产品版本。
  授权适配器与正式推理必须共用 `platform/llm/subscription-proxy` 导出的请求头工厂；
  仅有有效 token 仍可能因协议头缺失而被目录接口拒绝。不得通过重新授权、硬编码模型列表或跳过目录校验掩盖此问题。
- 上游请求失败的诊断只记录固定端点路径、HTTP 状态和安全错误码；
  不记录认证头、凭据、原始响应体或原始网络异常。授权有效与目录就绪须分别定位。
- 授权中心复用应用 API 的访问保护；GitHub 登录不为未开启应用访问令牌的 Web 部署提供用户隔离。

## 模块与验证

`modules/authorization` 拥有账户和设备登录，`platform/security/credentials` 只负责密文及本地密钥。
应用组合入口注入依赖；外部模块经 facade 使用能力，不深导入领域/适配器实现。
测试使用自有数据库和假上游；模拟授权通过不代表真实 Copilot 订阅已验证。

相关设计见 `docs/dev-workflow/2026-11-16-copilot-authorization/spec.md`。
