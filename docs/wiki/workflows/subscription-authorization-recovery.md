# 订阅账户授权与恢复

## 背景

GitHub 登录、Copilot 订阅可用性、模型目录和创作任务不是同一种状态。
把所有失败都解释成“重新登录”会使用户重复授权；把订阅错误当作 JSON 格式问题则会造成无效修复和隐式切换厂商。

## 当前规则

- 登录会话分为等待授权、校验订阅与保存/准备模型三个展示阶段，终态仍使用 pending/succeeded 等统一合同。
- 在等待和校验期间可取消；进入原子提交阶段后不把取消显示为已撤销授权。模型目录失败不能回滚已保存账户，
  应保留授权和待刷新配置，用户可在授权中心显式刷新。
- 状态 GET 不执行远程探测。登录后台轮询遵守 GitHub 的 interval、slow_down 和截止时间；
  前端查询频率不能增加上游轮询量。
- 首次 provider 创建与完成标记幂等保存。重新授权不覆盖用户默认模型、隐藏项和全局当前选择，
  人工删除过的自动 provider 不随重新登录复活。
- 目录只展示账户实际返回且传输受支持的模型；目录消失/能力未知不触发模型名猜测和静默替换。
- 短期令牌按需刷新，同账户刷新 single-flight；一个等待者取消不能取消其他正常调用。
- 退出先对保存的账户版本做并发校验，再清空凭据并递增代次。所有旧客户端、刷新结果和登录回调都受代次保护。
  provider 与创作数据保留，需授权连接仍在模型与厂商中可见。
- 恢复账户授权只恢复后续调用能力，不隐式继续原导演/章节任务。用户回来源工作台执行已有恢复命令；
  运行记录保持只读。
- 未配置模型时，授权中心不能被自动快捷配置向导遮挡，否则用户无法走完订阅授权。
  快捷配置可直接选择已授权的订阅连接，不要求 Key/地址；只有用户明确提交配置时才检测模型并初始化任务路由，
  登录与模型目录刷新本身不改写当前模型或任务路由。

## 失败分类

| 现象 | 事实与下一步 |
| --- | --- |
| GitHub token 无效 | 标记需重新授权，返回授权中心。不能进入 JSON 修复或付费备用厂商。 |
| 上游 403 | 根据明确结构化信号解释；未知原因保留访问被拒绝，检查订阅、模型和组织策略，不凭状态码断言无订阅。 |
| 模型目录失败 | 保留有效授权，显式刷新；未就绪连接不能被顶部选择或快速配置当作可用。若 token/账户接口成功而 `/models` 返回 400，先核对共享 Copilot 兼容请求头，而非要求重复登录；查 `[subscription.gateway]` 的端点、状态码和安全错误码，不输出 token 或原始响应。 |
| 上游 429 | 共享有效 Retry-After 冷却；没有头则不虚构恢复时间，不由代理重复发送。 |
| 流截断/取消/超时 | 不报完整成功，不重放已输出流，幂等释放账户许可。 |
| 主密钥缺失或损坏 | 保留密文和配置，恢复原凭据目录或按明确账户操作重新授权；禁止自动覆盖主密钥。 |
